## 二、决策与假设

### 2.1 关键决策

| 决策项 | 选择 | 理由 |
|---|---|---|
| 适配策略 | 混合策略 | 桌面端已通过 QA, 零回归风险; 移动端真响应式体验好 |
| 断点划分 | `<640px` 移动 / `640-1023px` 平板 / `≥1024px` 桌面 | 复用 Tailwind 默认断点 sm/md/lg, 无需改 tailwind.config.js |
| 平板布局 | 与移动共用, 微调列数与字号 | 减少工作量, 体验接近手机但更宽松 |
| 实施范围 | 9 业务页 + Header/Footer 一次到位 | 避免中途改设计导致前后不一致 |
| scale 触发阈值 | viewport ≥ 1024px 才启用 scale | 与 lg 断点对齐, <1024px 直接渲染响应式布局 |

### 2.2 假设

- 桌面端已通过 QA 的设计在 ≥1024px 视口下保持原样, 不重新 QA
- 移动端体验优先信息可读性, 允许部分装饰性元素 (如 SVG 装饰图标) 简化或隐藏
- 平板端不需要单独的"2 列卡片"等特殊设计, 与移动端共用布局
- 用户后续会基于真机/Chrome DevTools 移动端模拟器验收, 不需要专门测试设备

### 2.3 不做的事

- 不重构桌面端已通过的 1200px+scale 架构
- 不删除 `useAdaptWidth` hook (桌面端仍需)
- 不动 LoginPage/RegisterPage (已响应式)
- 不动 `src/components/home/` 下 13 个未使用遗留组件
- 不引入新的 UI 库 (如 shadcn/ui)
- 不做 PWA / 离线支持

## 三、技术方案

### 3.1 断点策略 (复用 Tailwind 默认)

| 断点 | 触发条件 | 行为 |
|---|---|---|
| base (默认) | `<640px` | 移动端单列布局, 字号最小, padding 最小 |
| `sm:` | `≥640px` | 移动端放大版, 部分模块 2 列 |
| `md:` | `≥768px` | 平板, 2-3 列布局, 字号适中 |
| `lg:` | `≥1024px` | 桌面端, 触发 Layout 的 scale 模式, 现有桌面布局原样生效 |

**关键约定**: 所有响应式 className 写法为 `[mobile-default] sm:[tablet-small] md:[tablet] lg:[desktop-override]`, 桌面端用 `lg:` 前缀覆盖移动端默认。

### 3.2 Layout 改造 — 条件性启用 scale

**文件**: [src/components/layout/Layout.tsx](file:///d:/VibeTest/bigsound/src/components/layout/Layout.tsx)

**改造点**:
- `useAdaptWidth` 新增返回值 `isMobile: boolean` (viewport < 1024)
- Layout 根据 `isMobile` 条件渲染:
  - `isMobile === false`: 现有 scale wrapper 不变
  - `isMobile === true`: 不套 scale wrapper, 直接渲染 `<div className="w-full">`, 让内部 `.container-page` 通过 CSS @media 变为响应式容器

**伪代码**:
```tsx
const { scale, wrapperHeight, isMobile } = useAdaptWidth(DESIGN_WIDTH);

if (!isMobile) {
  // 现有桌面端逻辑不变
  return <main style={{ height: wrapperHeight, ... }}>
    <div ref={wrapperRef} style={{ transform: `scale(${scale})`, width: DESIGN_WIDTH, ... }}>
      <Outlet />
    </div>
  </main>;
}

// 移动端: 不套 scale, 直接渲染
return <main className="w-full">
  <div className="w-full">
    <Outlet />
  </div>
</main>;
```

## 七、风险与缓解

| 风险 | 缓解措施 |
|---|---|
| Layout 改造破坏桌面端 | `isMobile` 严格判断 `viewport < 1024`, 桌面端走原逻辑分支, 不动现有代码 |
| Header 抽屉菜单 z-index 冲突 | 抽屉用 `z-[100]`, 高于 FloatingTools (z-40) 和 Header sticky (z-50) |
| SVG 横向滚动在 iOS 卡顿 | 添加 `-webkit-overflow-scrolling: touch` |
| 移动端 input 缩放 | 确保所有 input/font-size ≥ 16px |
| 桌面端 scale 模式下嵌套响应式 className 冲突 | 桌面端用 `lg:` 前缀覆盖, 默认值 (无前缀) 仅在移动端生效 |
| 部分页面固定像素遗漏 | 步骤 8 全站验收时用 Chrome DevTools 逐页扫描横向溢出 |
